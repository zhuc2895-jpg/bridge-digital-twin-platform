# 10: 单一实时采集循环与多客户端 WebSocket

**What to build:** 将实时数据生产与客户端连接解耦：后端只运行一个仿真/摄入循环，所有 WebSocket 客户端共享同一份实时状态。连接后以 1Hz 推送 `sensor_update` 消息，支持多客户端、断线清理、消息大小限制和采集循环异常隔离。

**Blocked by:** 08, 09

**Status:** ready-for-agent

- [ ] 任何数量的 WebSocket 客户端都只对应一个数据生成与摄入循环，不会因新增连接而重复生成、重复摄入或重复告警。
- [ ] 至少 10 个客户端可同时连接，并在连接后以 1Hz 接收同一批次传感器数据、最近 20 条告警和系统统计。
- [ ] `sensor_update` 消息包含 `type`、`sensors`、`alerts`、`stats`，单条消息不超过 10KB。
- [ ] 客户端断开、发送失败或异常关闭后连接资源被清理；重复连接和断开不形成内存增长。
- [ ] 单次推送从数据生成到客户端接收的延迟不超过 500ms。
- [ ] 采集循环中的单条坏数据或 AI 错误被隔离并记录，不终止其他客户端，也不终止后续推送。
- [ ] 覆盖单客户端、10 客户端、广播一致性、断线清理、消息契约和大小上限的自动化测试。
